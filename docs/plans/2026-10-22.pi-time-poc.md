# Plan - pi-time proof of concept

Source of the design: ~/create/research/memory-systems-oct2026/time-coverage.html, sections "Two tools, one contract" and "What the two tools could look like".
Durable state: `whats_next.md` at the repo root.

## Outcome

Running `./pi-time/pi-time` opens pi with two tools wired in, a ledger built from Jeremy's real project docs, a status line, a `/freshtime` command, and a startup notice that lists remaining work.
An ablation test shows the two tools together beat either one alone on synthetic fixtures.

## Layout

| Path              | Role                                                               |
| ----------------- | ------------------------------------------------------------------ |
| `freshtime-core/` | Contract types, SQLite open and schema, clock, traces, Jev client. |
| `freshtime-intf/` | Question plus session state to a `TemporalIntent`.                 |
| `freshtime-agnt/` | Freshness ledger: ingest, read by intent, verify, maintain.        |
| `pi-time/`        | Launcher, isolated pi agent dir, the pi extension.                 |
| `test/`           | Unit checks and the ablation test over `test/fixtures/`.           |

Runtime: Node 26 with type stripping, ES modules (`"type": "module"`), `node:sqlite`, `chrono-node`.
Imports use explicit `.ts` extensions and `import type`, with no enums and no parameter properties, so the same source loads under `node --test` and under pi's extension loader.

## Contract (freshtime-core/contract.ts)

`TemporalIntent`, produced by intf, consumed by agnt:

- `asof_mode`: `current` | `past` | `range` | `future` | `mixed` | `none`.
- `anchor`: `{ start, end, text }` in ISO dates, or null. A point in time has start equal to end.
- `basis`: `stated` (in this question), `inherited` (ambient as-of from an earlier turn), or `default` (nothing said, read as now).
- `kinds`: subset of the twelve kinds the question needs.
- `confidence`: 0 to 1.
- `path`: `jev` or `fallback`, so a silent Jev failure is visible.
- `query`: the question text with time phrases removed, for retrieval.

`LedgerFact`, returned by agnt:

- `id`, `project`, `section`, `text`, `source_path`, `kind` (volatility class).
- `valid_at`, `invalid_at`, `recorded_at`, `source_at`, `last_verified_at`, `verified_by`, `last_accessed_at`.
- `status`: `current`, `replaced`, `needs_check`, or `current_then` (held at the anchor of a past question).

## Domain mapping (fixed for the POC)

- Source files: `whats_next.md`, `HANDOFF.md`, `docs/handoffs/*.md` under ~/create and ~/repos (maxdepth 4, no node_modules or .git).
  Learning guides are deferred to an issue.
- A fact is one bullet or checkbox line.
  Its project is the directory that holds the file, or the repo root for `docs/handoffs/`.
  Its section is the nearest heading.
- Valid time is the date in the nearest dated heading (`## 2026-10-14 session`), else the date in the filename, else the file mtime.
- Replacement: a later dated "Next:" line in the same project replaces the earlier one.
  A `- [ ]` line replaced by `- [x]` with the same text is replaced.
  A line that no longer appears in its source on re-read is replaced at the time of detection.
- Volatility class, from ~/create/research/temporal-memory/scorer.py: `status` 7 days, `decision` 90, `preference` 365, `identity` never.
  Jev Choice assigns the class at ingest, with a keyword fallback.
- Verification action: re-read the source file and check the line still appears.
  Found means `last_verified_at = now` and `verified_by = source`.
  Gone means the fact is replaced and the file is re-ingested.
- Status at read, for `current`: replaced if `invalid_at` is set, needs_check if `now - last_verified_at` exceeds the shelf life, else current.
  For `past` with anchor A: facts with `valid_at <= A` and no `invalid_at` before A, labeled `current_then`, with no staleness check.
  For `mixed`: the past set at A plus what changed since A.

## Ablation test (test/ablation.test.ts)

Four configurations over the same synthetic fixtures and a fixed clock (2026-10-22):

| Config | Intent                                 | Ledger                                           |
| ------ | -------------------------------------- | ------------------------------------------------ |
| none   | none, reads at now                     | plain store with valid windows, FTS5, no checks  |
| intf   | intent parsed                          | plain store, as-of reads, no freshness           |
| agnt   | none, assumes now                      | full ledger, flags and verifies everything read  |
| both   | intent parsed, ambient as-of carried   | full ledger, verifies only facts read as current |

Fixtures include a source file edited after ingest, so only a re-read finds the change.
The script has single questions and one multi-turn case where "as of Oct 14" is stated once and the next question inherits it.

Scored separately, with the interaction term reported for each:

1. Fact selection: precision and recall against gold fact tags.
2. Status labels: share of selected facts with the gold status.
3. Harm: stale or replaced facts presented as current.
4. Verification spend: re-reads performed, and stale facts caught per re-read.

The committed test runs with the fallback path only.
A Jev-live run is reported separately in `docs/reviews/`.

## Observability

- `traces` table in the ledger DB: ts, tool, input summary, intent, path, latency, counts, error.
- Every Jev fallback writes a trace row with the reason, and the pi status line shows a fallback count.
- `/freshtime` in pi shows ledger counts by status, the last 10 traces, and remaining work.
- `node freshtime-agnt/cli.ts trace` prints the same outside pi.

## First run

The pi-time extension on session start lists open `agent:todo` issues from GitHub, with `REMAINING.md` as the offline fallback, and builds the ledger if it does not exist.
