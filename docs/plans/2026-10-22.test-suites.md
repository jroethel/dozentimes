# Plan - three test suites

Asked 2026-10-22: a pi-time end-to-end suite, a real-data replay from git, and a test method for each of the twelve kinds of time, each with its own data and generator scripts.
The six open issues will use these suites as their gate in a later session.

## Shared rules

- Test code only. A suite that finds a product defect reports it and does not fix product code, except where a section below allows a test hook.
- Synthetic data only in the repo. Real-data results go to `~/.dozentimes/replay/`, never into git, and reports print counts, never fact text.
- Same TypeScript rules as the repo: explicit `.ts` imports, `import type`, no enums, no parameter properties.
- A test for behavior that is not built yet is a real assertion marked `{ todo: "#<issue>" }`, so it fails today without failing the run, and flips when the feature lands.

## Suite 1 - twelve kinds (`test/kinds/`, runs in `npm test`)

One test file per kind, `test/kinds/<kind>.test.ts`, each with data under `test/kinds/data/<kind>/`.
`test/kinds/gen-history.ts` turns a JSON spec into a git repo with commits at given dates (`GIT_AUTHOR_DATE`, `GIT_COMMITTER_DATE`) and given final file mtimes, so record, source and valid time can be set apart on purpose.
`node test/kinds/report.ts` prints the coverage matrix: kind, tests passing, tests todo, and the method in one line.
`test/kinds/METHODS.md` states for each kind the method, the data, and what a pass proves.
The table gives the claim each kind's tests check and how much of it is built.

| Kind         | Claim                                       | Built today           |
| ------------ | ------------------------------------------- | --------------------- |
| event        | A period question returns facts dated in it | Heading dates only    |
| valid        | A replaced fact answers the past, not now   | Yes                   |
| record       | The ledger knows when it learned a fact     | Stamp yes, query todo |
| source       | An old doc imported today does not look new | mtime yes, git todo   |

## Suite 2 - real-data replay (`test/replay/`, `npm run replay`, not in `npm test`)

It walks git history of `whats_next.md`, `HANDOFF.md` and `docs/handoffs/*.md` in Jeremy's repos under `~/create` and `~/repos`.
Labels come from git, not from the rules.

- **As-of check:** replay each source's commits in order, ingesting each version at its commit date into a temp ledger.
  For sampled dates between commits, compare the ledger's past read with the lines in the git version at that date.
  This measures dating (heading dates against commit dates) and the past read path.
- **Freshness check:** ingest a version at T1, then for each later version at T2, compare the facts flagged `needs_check` at T2 with the facts that actually changed (line gone or replaced in the T2 version).
  Report precision and recall per volatility class, and the share changed by age per class, which is the data issue #4 needs.

Output: `~/.dozentimes/replay/<date>/report.md` and `results.json`, with counts and rates only.

## Suite 3 - pi-time end to end (`test/e2e/`, `npm run e2e`, not in `npm test`)

It drives real pi with glm-5.3 in RPC mode through the pi-time agent dir, over a temp copy of the ablation fixtures.

- Before pi starts, the harness builds the ledger with `DOZENTIMES_NOW` at the ingest date.
  It starts pi with `DOZENTIMES_NOW` at the question date, waits for startup, then applies the edits, so they happen behind the ledger.
- It sends the seven ablation questions as one conversation, then records the tool calls, tool results, each turn's reading and the final text.
- Deterministic checks: `dozentimes_ask` was called on each turn, and each turn's mode, anchor and basis match the gold.
- Judged checks, by Jev Noul on the final text: each must fact is stated, no harmful fact is presented as currently true, and the answer states the time it is answering for.
- A fallback run with a bad `TYPESAFE_API_KEY` for the reading checks that an answer still arrives and the trace shows the error.
- `--runs N` repeats the conversation and reports pass rates, because model output varies.

Allowed test hook: an env flag in the pi-time extension that writes each turn's reading as JSON to a file, if RPC mode hides stderr.
