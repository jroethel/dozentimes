Time map

The twelve kinds of time in dozentimes, placed by who uses each one and how long its value lasts.

1. Interface against agentic

Left is time that comes from the people in the conversation. Right is time the agent's own machinery writes and reads. Up is how long a value stands as written, in four bands: redone every turn, carried through one session, stored but rewritten, and written once. Both charts use the same bands.

2. Three lanes and four lifespans

The agentic side splits into the work agents do behind the scenes and the oversight of that work: traces, evals and audit. The lifespan bands from chart 1 become rows.

dozentimes-intf dozentimes-agnt in the code, not one of the twelve

Two things stand out. The oversight lane holds only record and verification, though the code already writes two more times there: a row in the traces table for each traced tool call, and a row in the checks table for each re-check (dozentimes-core/db.ts). Nothing in the code deletes from either table, so both sit in the written-once row. The lower right is empty: no agentic time lives only for a turn or a session, because everything the agent keeps goes into the ledger.
