1. Project summary and scope

Two time tools share one contract, and pi-time runs both inside pi.
dozentimes-intf turns a question plus conversation state into a TemporalIntent (as-of mode, anchor, basis). dozentimes-agnt is a freshness ledger of dated facts with a volatility class, last-verified date and status. dozentimes-core holds the contract, SQLite schema, traces and Jev client. ./pi-time/pi-time launches pi with its own agent dir and the dozentimes extension.
The design is the "Two tools, one contract" sketch from research/memory-systems-oct2026/time-coverage.html, built backwards from a test.
The ledger reads Jeremy's own project docs and keeps the result outside the repo.
Sources are whats_next.md, HANDOFF.md, docs/handoffs/*.md and learning_guide*.html under ~/create and ~/repos. The ledger lives at ~/.dozentimes/ledger.db.
The repo stays public at Jeremy's choice, so no extracted fact, session transcript or auth link may enter git.

2. Architectural principles that emerged

Code finds candidates and does date arithmetic, Jev only judges.
chrono-node parses date phrases. Jev picks the as-of mode, picks an anchor from the parsed candidates (never writes a date), and answers whether a question changes the period. Every Jev call has a deterministic fallback.
A fact is last confirmed when its author wrote it, not when the ledger read it.
At ingest last_verified_at is the fact's valid_at and verified_by is author. Only a source re-read moves it to today with verified_by = source.
Found in the first interactive run on 2026-10-22: the status line said "0 stale" across 809 facts because ingest stamped every fact as verified today. After the fix, 342 were stale.
An inherited as-of date survives unless the question changes the period.
Jev's mode choice cannot override an inherited reading. Only the "does this question change the period" judgment can.
Live Jev read the follow-up "And the next step for alpha?" as a future question and dropped the inherited 2026-10-14, which made the Jev ablation lose one question. The fallback rules had it right.
Handoffs are snapshots, so a later handoff's state section replaces the earlier one.
State-like sections (State, Next step, Recent artifacts, Open ...) in a later-dated handoff of the same project replace that section in earlier handoffs. Within one file, an earlier same-day Next: line is replaced by a later one.
Before this rule, 0 of 809 real facts were ever replaced, because real handoffs use section headings where the rule only knew Next: lines. After it, 48 were.
Every Jev failure is loud.
A failed call writes a trace row with the error, the status line shows jev FALLBACK n, and /dozentimes trace shows the row as ERROR. The answer still arrives on the fallback path.
Checked on 2026-10-22 by launching pi-time with a bad TYPESAFE_API_KEY.

3. Design-process learnings

Score fact choice, status labels, harm and re-reads separately, or the 1+1=3 result is rigged.
A single "right fact with the right status" score gives each tool half of a conjunction, so a positive interaction is guaranteed by construction. Measured separately, status accuracy only adds up (interaction 0.00), and harm drops by more than the sum (interaction -2).
Raised by the advisor before the test was written. The honest result is the stronger one: the ledger alone removes no harm, because it shows the newest fact as true for past questions.
Re-read spend depends on question order, so it needs a cold mode.
In the carried script, one early "now" question freshens the facts later questions use, so ledger-only and both spent the same 4 re-reads. With a fresh ledger per question (--cold), ledger-only spends 24 and both spend 9.
The first test asserted both.checks < agnt.checks on the carried script and would have failed. The assertion moved to the cold run, where it measures what it claims.
A score on labels written next to the rules is a regression check, not accuracy.
The rules scored 20/20 and Jev 19/20 on 20 labeled intent questions, but the labels and rules came from the same worker. Issue #1 asks for a blind set.
Assert the mechanism, not a coincidence of the fixtures.
An early assertion agnt.harm == none.harm held only because the two were wrong on different facts. The test now checks per question: ledger-only has harm on the past and inherited questions (q2 to q4) and none on the "now" one (q1).

7. Operational learnings

Run pi in json mode with stdin closed.
pi --mode json ... < /dev/null. Without the redirect it hung from a non-TTY harness. Assert on tool_execution_end records.
In the TUI, never mirror extension output to stderr.
Stderr lines tear the pi screen. The extension writes to stderr only when ctx.hasUI is false.
Test the first run on a throwaway ledger so the real first run stays a first run.
Every E2E used DOZENTIMES_DB in $TMPDIR. ~/.dozentimes does not exist yet.
pi rewrites its settings file.
pi adds lastChangelogVersion to pi-time/agent/settings.json, so the committed copy includes it.
A herdr side pane is the closest thing to Jeremy's own first run.
herdr pane run to launch, herdr agent prompt --wait to ask, herdr pane read to see the screen. This is how the stale count, the torn screen and the fd download were found.

8. Updates - test suites (2026-10-22)

"Line still in the file" is not "still true" for logs and handoffs.
The first replay counted every rule replacement of a line still present as a miss, and reported recall 0.53. whats_next.md keeps old Next: lines below newer ones, and handoff folders keep old files. With rule replacements counted separately, recall against git is 0.998.
Caught by the orchestrator reading the first replay report, before the numbers reached an issue.
A replacement closes at its successor's date, not the newest one's.
Rule (b) closed every older Next: at the newest date when a file was read in one pass, so a past read between sessions showed a stale step. Found by test/kinds/valid.test.ts, fixed by chaining each one to its successor.
A removed line that comes back must be reopened.
The unique key (source, section, text) made a re-added line skip insertion and stay invalid. This caused 1,998 replay misses. It is now reopened. The gap between removal and return is lost (a ponytail: comment marks it).
Explicit "now" words beat Jev's mode.
In the e2e suite, live Jev read "What is the next step for alpha now?" as future. With no date in the question, a "now" word is a stated reading that Jev cannot override. This is the second guard on Jev after the inherited-as-of guard.
On every labeled set so far, Jev's intent reading adds nothing over the rules. Its value stays untested until the blind set (#1).
A judge question has to ask about the time the question asks about.
"Does the answer present X as currently true?" failed correct historical answers that also mentioned the present. The e2e judge now asks whether X is presented as true for the asked date or period, and whether a fact is included in any wording.
The 7-day status shelf life is too short on real data.
The replay with Jev classes found 4,672 status facts flagged and 14% of them changed in git. The share changed was 7% at 0 to 7 days and 35% at 31 to 90 days. The data is on issue #4.
Test runs must not leave a ledger in the user's home.
During the worker runs something created ~/.dozentimes/ledger.db with the real corpus (most likely a pi run without DOZENTIMES_DB, not traced). It was deleted so Jeremy's first run is still a first run.

9. Updates - the video, A Dozen Times (2026-10-22)

One timeline file keeps picture, sound and docs in sync by construction.
video/dozen/src/timeline.ts holds every scene time, word and sound cue. The painters and the score both read it, so a cue moved once moves in both. The as-of flap times are solved from the scrub easing and stored there too, instead of being estimated in two places.
Sub-frame motion blur steps on thin strokes at whip speed.
At the whip spin, 8 and then 24 sub-frames still left month labels as stepped copies, because each stroke is narrower than the gap between sub-frames. Halving the ring's own wind-up and adding a blur that scales with speed made it read as a smear. The still renderer never runs sub-frames, so this only showed on frames pulled from the encoded preview.
Caught because the advisor asked for frames at the fastest moments before the 4K render, not after.
Canvas blur is in device pixels, letter spacing is not.
In skia-canvas, ctx.filter = "blur(r)" ignores the scale transform while letterSpacing follows it. A blurPx helper scales blur by the render scale, so 1080p QC frames and the 4K master look the same.
A mix can be checked without listening.
The first score had its lows 10 dB over the mids, which laptop speakers would mostly lose. Band levels (below 150 Hz, 150 Hz to 2 kHz, above 2 kHz), a spectrogram, and momentary loudness against the 3-second level found it, and the same checks found the twelve hook pings jumping 7.7 LU over a quiet bed.
RGB frames need an explicit BT.709 matrix on the way to YUV.
The encode converts with scale=out_color_matrix=bt709 and tags BT.709. A pixel comparison of an encoded frame against the source frame matched within 1 level of 255.
Search summaries misattribute quotes.
Two of three trend claims in a search summary came from a different page than the one it implied, and the third was on neither page fetched. Each quote in the storyboard was fetched from its page before it shipped, and the unconfirmed one was cut.
A re-issued prompt with an earlier result on disk reads as a miss.
The same request had already produced a cut in video/. It was kept, its source committed, and the new film built beside it instead of patched, so both can be compared.

10. Updates - the ledger issues chain (2026-10-22)

Six issues closed through one serial plan, with the decisions D1 to D16 recorded as they were taken.
Issues #3, #4, #5, #6, #7 and #12 ran as eight serial tasks in docs/plans/2026-10-22.I3.I4.I5.I6.I7.I12.ledger-issues-plan.md, every task touching dozentimes-agnt/ledger.ts, each ending in npm test with fail 0.
D1, Jeremy: rule (d) applies only between handoffs that share a slug, or where the later one names the earlier file.
All 1842 unique rule (d) cases in the 2026-10-22 replay crossed into a different file with a different slug, and project-wide (d) let one task's State close another task's.
D2, planner: same-day order comes from the naming reference, not file mtime, and same slug plus same date never replaces.
The ledger stores no time of day, and the naming reference gives a direction without a clock.
D3, planner: new facts.closed_by and checks.kind columns record which rule closed a fact and the class a check was made under.
#3 needs to tell a user close from a removed line, #6 needs to tell a rewording from a change, and the replay reads the rule from the column instead of guessing from text.
D4, planner: the model records statements through a new ledger_record tool, by fact id, and the tool echoes the fact text.
D5, planner: a changed value becomes a conversation fact with source_path conversation:<project>.
A fact with a made-up file path would be closed by rule (c) or verifyFact the first time it went stale.
D6, planner: a user close survives re-ingest while the file line is unchanged; a later doc edit does not yet close a conversation fact.
The second half is the open follow-up, filed at checkpoint D.
D7, planner: a statement about a fact that is not live is refused, except "still holds" on a user-closed fact, which undoes the close.
This is the undo for a wrong ledger_record call that the Rubix review asked for.
D8, Jeremy at checkpoint C: exponential current-status fit on source and reword checks, at least 30 distinct facts, stale risk 0.25, clamped to 1 to 365 days.
Checks rows from source re-reads only exist for facts already past their shelf life, so the data is censored, and user statements are excluded because the person mostly speaks up when something changed.
D9, planner: reclassify in maintain, at most 40 rows (one Jev request) per call, never at startup.
One Jev chunk can wait 30 seconds, so reclassifying thousands of rows at pi startup during a Jev outage would stall startup for minutes.
D10, planner: rewording is word-set Jaccard of at least 0.8 within one file and section, with equal number tokens and equal negation words, no Jev.
A changed port number in a 12-word line scores 0.85 and an added "not" scores 0.91, so length alone does not protect a long line.
D11, planner: rule (e) replaces a status-family bullet with a later one in the same file when the text after the prefix overlaps 0.5 or more.
"Waiting on the vendor price sheet" and "Waiting on the DBA for credentials" are two open dependencies, so the remainder must overlap.
D12, Jeremy at checkpoint B: narrative bullets in older handoffs are not replaced.
A narrative bullet records an event that stays true, so its staleness is left to shelf lives.
D13, planner: replay gates use keyword classification and a fresh baseline taken before Task 1.
D14, planner: the end-to-end statement turns live in a new test/e2e/statements.json.
D15, Jeremy: replay gets a --show-sample flag that prints 20 closures of one rule to the terminal only, never to a file.
The replay gates count how often a rule fires, not whether it fired correctly, so a person has to grade a sample.
D16, driver: rule (d) closes E at the earliest continuer, like rules (b) and (e), in every ingest order.
Added to the log after checkpoint A, when a review found that different ingest orders gave different closes.
The e2e suite now proves the statement path through real pi.
27 of 27 turns over 3 runs, with the record turn calling ledger_record and the follow-up question answered from the conversation fact, and the fallback run answering 9 of 9.

11. Updates - the rename to dozentimes (2026-10-24)

A project rename touches state outside the repo, not just text.
The ledger keys facts by absolute source_path and takes project from the folder name, so moving the folder alone would have ingested this repo's facts a second time. The ledger rows, the git worktrees under ~/.dozentimes/worktrees/ and the installed ~/.local/bin/pi-time launcher moved with the repo.
Renaming the product exposed a doubled tagline in the film.
A Dozen Times ends on "Now I've told you a dozen times." and then the product mark, which now reads "dozentimes". The films were left unrendered, and issue #15 holds the rewrite.
